# 从原型到需求规格说明书（Prototype-to-PRD）实战方法论

本技能总结自 **XLab 2D 物联网虚拟仿真系统（从 V1 到 V5.2.0 首发基线版）** 从 0 到 1 的完整产品化与规格说明书编写经验。旨在建立一套**高保真、可复用、结构严谨、面向 AI 智能体与工程研发落地**的原型逆向提取与需求文档编写标准，并在每一次需求迭代中持续进化。

---

## 1. 核心工作流程（5步工作法）

```mermaid
flowchart TD
    A[原型代码 / UI 交互分析] --> B[Step 1: 业务闭环与领域实体建模]
    B --> C[Step 2: 页面与组件结构化拆解]
    C --> D[Step 3: 工业协议与技术参数提炼]
    D --> E[Step 4: 规范化 Markdown PRD 输出]
    E --> F[Step 5: 版本对齐与 Skill 持续沉淀]
```

### Step 1: 业务闭环与领域实体建模（Domain Modeling）
- **抓取全局路由与页面状态**：从路由入口（如 `App.tsx`、`routes`）识别系统核心页面（首页、设计器、控制台、详情大屏、智能体）；
- **梳理核心数据实体（Entities）**：识别系统底层的核心模型（如系统设备库、自定义设备、仿真工程、物料素材、拓扑节点、拓扑连线、遥测数据、反向控制状态）；
- **绘制业务全景流转链路**：明确正向主链路（物料选型 -> 拓扑设计 -> 仿真验证 -> 监控发布）、逆向分支（撤销重做、克隆副本、下架删除）与异常拦截（冲突告警、非法连线拦截）。

### Step 2: 页面与组件结构化拆解（Screen-to-Spec Mapping）
针对原型中的每一个功能视窗或组件模块，按照以下标准化维度进行“地毯式”拆解：

1. **多维筛选与关键词搜索栏**：
   - 必须输出**【筛选项定义表】**（筛选条件、控件类型、选项值/输入规则、默认值、校验与限制）；
   - 明确多筛选项之间的逻辑关系（通常为 `AND` 关系）与一键清空/重置筛选交互规则。
2. **多层级分类导航树**：
   - 明确层级深度（一级大类 -> 二级子类 -> 三级叶子节点）；
   - 说明全局控制项（【展开全部】/【折叠全部】）的递归逻辑；
   - 标明各分类行右侧的**数量统计徽标（Badge）**及其展开高亮联动效果。
3. **列表/卡片/双模视图（Grid vs List）**：
   - 必须输出**【列表展示字段表】**（字段名称、展示形式、业务说明）；
   - 明确双模视图（方块宫格 Grid vs 紧凑列表 List）的排布规格、展示侧重点（宫格注重直观图文、列表注重型号与 ID 参数）；
   - 明确排序规则（最新发布、最多浏览）、分页与缺省空态（Empty State）引导。
4. **分步向导弹窗与模态对话框（Wizard / Modal）**：
   - 必须输出**【表单字段定义表】**（表单字段、控件类型、**是否必填**、**字符长度 / 数值范围限制**、默认值、校验与说明）；
   - 明确自适应分步逻辑（如根据业务类型动态适配步骤）与**动态表单配置消费**（动态字段渲染及敏感字段脱敏规则）；
   - 明确防误触关闭确认、“上一步”草稿保留机制，以及**删除/破坏性操作的二次确认弹窗规范**（存在子级或关联引用时需弹窗提示阻断原因）；
5. **复杂画布与拓扑工作区（Canvas / Workspace）**：
   - 明确视口缩放极值边界（如 `25% ~ 200%`）、对齐与网格吸附步长；
   - 明确连线规则：锚点吸附、介质标注、自环拦截与重复连线阻断；
   - 明确**双重添加模式**：鼠标悬浮快捷添加（`Hover + Add` 阶梯自动偏移）与 HTML5 原生拖拽（`Drag & Drop` 精确落点）。
6. **AI 智能助手/智能体（Agent Widget）**：
   - 交互形态：右下角悬浮气泡、抽屉视窗、居中沉浸大窗、多模态附件上传（图片/文档）；
   - 能力边界划分：明确不同工作模式（如通用知识检索模式 vs 专属交互/生成模式）的功能范围与操作边界；
   - 核心能力：自然语言建模、语义检索、端到端方案生成、指令下发与参数配置辅助。
7. **数据总览与指标看板（Overview Dashboard）**：
   - 必须**逐一写明每个核心指标卡（含主/副指标）、排行榜（排序口径、切片数量与进度条百分比公式）及趋势图表（时间预设、自定义跨度限制、区间汇总与 Tooltip 衍生指标）的精确计算规则**，严禁仅罗列指标名称而遗漏计算口径；
8. **多视角复用、配置联动与可见性范围（Multi-Scope & Visibility）**：
   - 当系统存在多权限视角（如局部管理视角 vs 全局运营视角）时，子章节严格按原型菜单实际名称命名；基础视角全面拆解，高阶视角重点详述专属功能，复用模块简明对比新增的全局筛选维度、字段差异与作用域变化；
   - 明确**前后台配置联动关系**（配置源、前台消费位置、默认兜底规则与实时同步机制）及**数据可见性与发布范围**（如草稿/已发布状态边界、租户/机构数据隔离与跨端同步范围）。

### Step 3: 工业协议与技术参数提炼（Protocol & Technical Specs）
针对工控、物联网或特定技术领域的原型，必须下沉到数据链路层：
- **Modbus 寄存器映射表**：明确属性名、功能码（`0x01/0x03/0x04/0x05/0x06`）、起始地址（Hex/Dec）、数据长度（Words/Bits）、换算公式（`RAW / 10.0`）、物理单位与量程；
- **模拟量（Analog）转换公式**：明确 0~5V/4~20mA 信号范围与实际物理量转换模型及 ADC 采样映射；
- **设备素材防删保护**：存在拓扑或工程引用时禁止物理删除，保障资产一致性；
- **状态机与防连击保护**：执行器指令下发时的 Loading 锁定与状态防抖翻转。

### Step 4: 规范化 Markdown PRD 输出（AI-Optimized Markdown Formatting）
为了让需求文档兼具**极佳的人类可读性**与**极高的 AI 上下文解析准确度**，必须严格遵循以下排版规范：
- **标题简洁与菜单对齐原则**：各级标题保持简洁直白，不要附加过多修饰或冗长解释；后台控制台功能章节必须严格按照原型左侧菜单真实名称命名；
- **严禁使用悬空断行**：表格必须与前后的文本之间留有空行（`\n\n`）；
- **表格列对齐统一**：表头加粗，对齐符统一使用 `:---`（靠左对齐）；
- **列表格式统一**：无序列表使用 `- **属性名称**：详细说明`，有序操作流程使用 `1. `, `2. `, `3. `；
- **纯净文本无图原则（面向 AI）**：剥离界面截图引用（`images/...`），用详尽的结构化字段与状态机代替图片，避免多模态 token 浪费与图片丢失失效；
- **文档完整性要素**：包含文档属性表、目录（TOC）、需求背景、名词术语表、功能规格、非功能需求、测试关注点与验收基线、其他注意事项（若用户指定精简或暂缓填充部分章节，按用户要求删除或保留空章节占位）。

### Step 5: 版本对齐与 Skill 持续沉淀（Iterative Skill Refinement）
- **版本基线对齐**：当用户提供手动批注版、新评审意见或新版 `.docx` 时，先提取核心差异，若原型代码尚未实现新口径，需评估并同步调整原型代码与需求文档；
- **版本递增规范**：后续每次对 PRD 文档进行内容调整或迭代更新时，必须同步递增版本号（如 `V1.0.0` -> `V1.0.1` 或 `V1.1.0`），确保文档文件名、一级标题及【文档属性表】中的版本号保持一致；
- **通用方法论沉淀机制**：在后续使用本技能编写、评审或迭代 PRD 的全过程中，**每当提炼出跨项目通用的文档结构偏好、需求拆解维度、校验规范或排版标准时，应自动补充沉淀到本 `SKILL.md` 中**；**具体项目的业务细节与定制逻辑仅体现在对应 PRD 中，不写入本通用 Skill**。

## 2. 原型逆向提取标准检查清单（Checklist）

在编写或审查每一份 PRD 时，逐项对照以下清单，确保零遗漏：

| 模块类别 | 核心检查点 | 常见遗漏盲区（需重点补充） |
| :--- | :--- | :--- |
| **基础信息** | 文档版本、生效时间、原型对应路由、标题简洁度 | 历史版本演进与版本号同步递增、菜单名称严格对齐、脱敏规则 |
| **筛选项** | 控件类型、候选值、默认值、校验限制 | 筛选项之间的逻辑关系（AND）、一键重置与清空逻辑 |
| **表单与弹窗** | 字段名、控件类型、默认值、提交确认逻辑 | **是否必填**、**字符长度 / 数值范围限制**、删除前**二次确认弹窗**、动态表单消费 |
| **导航树** | 层级深度、展开/折叠交互、激活样式 | **展开全部/折叠全部**、各层级右侧**数量徽标（Badge）**、子节点删除保护 |
| **数据列表** | 字段名称、展示形式、数据格式、排序口径 | **宫格视图（Grid）与列表视图（List）的区别说明**、排序取数依据、缺省空态 |
| **操作交互** | 点击、悬浮、拖拽、弹窗触发、多阶段状态机 | **Hover+Add / Drag&Drop**、安全倒计时确认锁、进度条状态反馈、纯文本日志 |
| **数据总览** | KPI 卡片、排行榜、趋势折线/柱状图 | **每个指标的精确计算公式与口径**、进度条占比公式、日期跨度限制、Tooltip 衍生指标 |
| **配置与联动** | 后台配置项与前台展示/消费的映射关系 | **配置源与同步机制**、未配置兜底回退、**发布状态与租户/多端可见性边界** |
| **协议与硬件** | 通信协议标签、供电规格、电气引脚 | **全视图协议彩色胶囊标注**、Modbus 寄存器表、模拟量量程公式 |
| **工程/物料克隆** | 复制按钮触发、模态弹窗表单、默认命名规则 | **`${原名称} 副本` 命名回填**、深拷贝拓扑连线与参数逻辑 |
| **BOM 设备清单** | 硬件图、名称、类型、协议、使用台数 | **清单内单设备一键克隆为私有自定义设备功能** |
| **AI 智能助手** | 视窗形态、大窗切换、多模态图文输入、能力边界 | **不同交互模式的能力边界划分**、语义检索、自然语言建模 |
| **多视角对比** | 局部管理视角 vs 全局运营视角权限与功能范围 | 基础模块详述 + 高阶视角差异对比 + 平台级底座功能重点拆解 |
| **非功能指标** | 画布 FPS、查询过滤时延、首屏加载时间 | 浏览器兼容版本、屏幕分辨率自适应、异常拦截与本地缓存隔离 |

## 4. 技能演进与维护准则
1. **仅沉淀通用方法论**：在后续使用本技能编写或迭代 PRD 的过程中，凡涉及**通用**的文档规范、拆解维度、校验表结构或交互提取盲区，AI 应自动同步补充至本 Skill；**与具体业务项目绑定的需求规则仅保留在项目 PRD 中，不写入本 Skill**；
2. **每次迭代更新**：当发现新的通用界面模式（如新图表引擎、多端联动、动态表单规范）时，将通用拆解模式补充到第 2 节（检查清单）与第 3 节（模板）；
3. **持续保持纯净**：始终坚持纯文本与标准 Markdown 格式，杜绝任何外部未定义宏或破损图片标签，确保 AI 与工程师均可无缝读取并高效实现。
